# Pstack 0.15.0 port decisions

Reviewed on 2026-09-08 against immutable upstream commit
[`71ed0d1076fec562c1b74ee353121a8d00f75382`](https://github.com/cursor/plugins/tree/71ed0d1076fec562c1b74ee353121a8d00f75382/pstack).
The previous baseline was pstack 0.14.8 at `93b00b89ef425a9c1bac0d0b317dfc49c930ac99`.

The delta is three upstream commits: `e8d856f` (a density and mannered-prose pass across the skills, plus two new principle leaves), `d7cde2b` (semicolons, em dashes, and connector colons in skill prose replaced with periods or commas), and `71ed0d1` (version bump and README count sync). The update report lists 95 changed paths: 78 imported, 6 excluded, 11 review.

## Released guidance

- Two new principle leaves ship as `copy` imports: `principle-attack-the-premise` 0.1.0 (question the premise that two or more failed fixes shared, after a per-actor census) and `principle-test-behavior-not-implementation` 0.1.0 (a test calls the code the way its users do and asserts a literal expected value; delete a test that would still pass if every imported function returned `undefined`). They are user-only leaves, indexed by `engineering-mode` in the Core and Verification groups in upstream's order.
- `how` 0.1.1 loses Critique mode, mirroring upstream. `references/critic-prompt.md` and `references/critique-rubric.md` are deleted, the description no longer offers a critique, and the skill is explain-only. `adversarial-review` remains the owner of structural judgment.
- `unslop` 0.1.1 drops the "Adding soul" section and rules 1, 2, 4, 6, and 21 (numbers stay as gaps because other skills cite them), and adds rule 32 (mannered prose) and rule 33 (over-compression).
- `technical-writing` 0.1.1 proposes new jargon offenders as an `unslop` addition in the reply instead of editing that skill, and treats a pull-request description as a one-minute briefing (written for the user to post; no PR step is added).
- `principle-subtract-before-you-add` 0.1.1 changes its description from "dead weight" to "dead code"; the generated principle index and the guide follow.
- Every other imported skill receives upstream's prose-density edits where the local sentence still matched: intensifiers dropped, semicolon sentences split, justification tails and figurative phrases removed. Local adaptations (host neutrality, the solo agent policy, Git authority gates, renamed concepts, inline fallbacks) are unchanged.

Automatic invocation is unchanged: `engineering-mode`, `typescript-best-practices`, and `unslop` remain model-invocable; every principle leaf stays user-only with `policy.allow_implicit_invocation: false`.

Install and update commands are unchanged. No migration is required. Users receive these changes with `bunx skills update` after the release reaches `main`.

## Versions

Plugins whose installed text changed received a patch bump (SKILL.md and `.codex-plugin/plugin.json` together). Plugins whose installed text did not change keep their version even where upstream changed the source, because only the regenerated notice differs: `arena`, `automate-me`, `blast-radius`, `configure-agent-models`, `review-code-comments`, `swarm`, and `worktree-cleanup`. Plugins with no upstream change at all (`bro`, `create-verification-skill`, `maintain-verification-skill`, `principle-exhaust-the-design-space`, `principle-make-operations-idempotent`, `principle-outcome-oriented-execution`) also keep their version.
