# Pstack component extraction inventory

## Question

Which parts of pstack should move into `petalas/skills`, and which parts need to
change or stay behind, if the result must work outside Cursor, support a solo
developer, allow internal subagent coordination, and never communicate with
other people?

## Sources and method

This inventory reads the pstack subtree at commit
[`799151d91b6e12ee7dbd09f708eec108d7de9b3b`](https://github.com/cursor/plugins/tree/799151d91b6e12ee7dbd09f708eec108d7de9b3b/pstack).
The baseline source links are pinned to that tree. Changed classifications below link to the reviewed 0.14.8 revision. See [the 0.14.8 port decisions](pstack-0.14.8-update.md) for every changed path. It also checks the target at
`ff2cfb9b4540b0691fa0165b9fd4895bc34eb4dd`: its
[`AGENTS.md`](https://github.com/petalas/skills/blob/ff2cfb9b4540b0691fa0165b9fd4895bc34eb4dd/AGENTS.md)
and
[`CONTRIBUTING.md`](https://github.com/petalas/skills/blob/ff2cfb9b4540b0691fa0165b9fd4895bc34eb4dd/CONTRIBUTING.md)
establish one plugin per directory, mirrored skill and manifest versions,
Codex metadata, ASCII-only text, and Prettier as the current quality gate.

The classifications mean:

- **Copy**: keep the instructions or artifact unchanged. Mechanical packaging,
  relative-link repair, target metadata, and required license notices do not
  count as semantic changes.
- **Adapt**: preserve the workflow but replace Cursor paths, built-ins, tool
  names, model slugs, transcript discovery, or external-write behavior.
- **Extract concept**: keep a smaller idea, often by folding it into an existing
  target skill, rather than porting the source component.
- **Exclude**: do not port it. It is either team-communication machinery,
  Cursor-only product plumbing, or an automated PR/review workflow explicitly
  deferred by this effort.

For an installed destination, `Copy` maps to manifest disposition `copy`.
Both `Adapt` and a ported `Extract concept` map to `adapt`. Each manifest entry
names the exact `inventorySource` row that controls this reconciliation, so the
validator can detect drift between this inventory and the installed import.
Each source-to-installed-file mapping also pins the exact source blob SHA-256
and a `pstack-markdown-v1` normalized SHA-256. That normalization changes line
endings, removes only the destination `version` frontmatter field, treats
frontmatter field order as formatting, and applies the repository's pinned
Markdown formatting. Copy-class destinations must match that normalized hash.

This is a planning artifact. It does not copy or modify any skill.

## Hard boundary for every destination skill

Internal delegation is allowed. Main agents and subagents may spawn, wait for,
and communicate with one another. External communication is not allowed, even
when an integration is installed and authenticated.

Every adapted or newly extracted skill needs one shared rule:

> Never send, post, reply, comment, file, publish, or otherwise direct a message
> to another person through Slack, Teams, Discord, email, DMs, issue trackers,
> pull-request reviews, review threads, chat connectors, or similar external
> systems. Do not delegate external communication to a subagent. Produce a local
> draft or concise handoff for the user to send manually.

Read-only use of source control, issue history, documentation, observability,
error tracking, and analytics remains useful to a solo developer. Team chat is
different: the user does not need it, and the Slack-specific evidence and
automation paths should be removed entirely. Repository mutations such as a
push or pull request are not implicit in these skills; they remain governed by
an explicit user request and the target repo's own delivery rules.

## Findings

1. **Most of the intellectual core is portable.** The 21 principle skills,
   TDD, technical writing, TypeScript guidance, `unslop`, `bro`, `teach`, and
   nearly all architecture/review prompt templates contain no Cursor runtime
   dependency. The main principle index confirms that these are deliberately
   small leaf instructions rather than one Cursor workflow
   ([source](https://github.com/cursor/plugins/blob/799151d91b6e12ee7dbd09f708eec108d7de9b3b/pstack/skills/poteto-mode/SKILL.md)).
2. **Cursor coupling is mostly syntactic, not conceptual.** `architect`,
   `arena`, `how`, `interrogate`, `swarm`, and the general build playbooks use
   hard-coded `Task`, `AskQuestion`, todolist, cloud environment, model slug,
   `~/.cursor`, and transcript conventions. Their workflows survive if those
   calls become capability-based instructions and inherit the host's available
   subagent API
   ([arena](https://github.com/cursor/plugins/blob/799151d91b6e12ee7dbd09f708eec108d7de9b3b/pstack/skills/arena/SKILL.md),
   [how](https://github.com/cursor/plugins/blob/799151d91b6e12ee7dbd09f708eec108d7de9b3b/pstack/skills/how/SKILL.md),
   [swarm](https://github.com/cursor/plugins/blob/799151d91b6e12ee7dbd09f708eec108d7de9b3b/pstack/skills/swarm/SKILL.md)).
3. **The disallowed behavior is concentrated and easy to fence.** Benny is a
   Slack-to-tracker-to-PR automation pack. `why` has one real-time-team-chat
   investigator. `reflect` can automatically file backlog work. Shipping,
   babysit, autopilot, Bugbot, and watch-pr workflows write or react to PR
   review state. Those components should be excluded or stripped of the write
   path rather than protected by a runtime warning
   ([Benny intent](https://github.com/cursor/plugins/blob/799151d91b6e12ee7dbd09f708eec108d7de9b3b/pstack/automations/benny/FOR_AGENTS.md),
   [`why`](https://github.com/cursor/plugins/blob/799151d91b6e12ee7dbd09f708eec108d7de9b3b/pstack/skills/why/SKILL.md),
   [`reflect`](https://github.com/cursor/plugins/blob/799151d91b6e12ee7dbd09f708eec108d7de9b3b/pstack/skills/reflect/SKILL.md)).
4. **A monolithic pstack clone would conflict with the target repository.** The
   source has one Cursor manifest that registers a skill root and two custom
   agents. The target ships one independently installable plugin per directory
   with Codex metadata. Each reusable skill should therefore become its own
   plugin, with a separate optional host-neutral router replacing
   `poteto-mode`
   ([source manifest](https://github.com/cursor/plugins/blob/799151d91b6e12ee7dbd09f708eec108d7de9b3b/pstack/.cursor-plugin/plugin.json),
   [target convention](https://github.com/petalas/skills/blob/ff2cfb9b4540b0691fa0165b9fd4895bc34eb4dd/AGENTS.md)).
5. **Direct copying carries a license obligation.** Pstack is MIT licensed, and
   the copyright and permission notice must remain with substantial copied
   portions. The target should add a third-party notice or retain a license file
   in each substantially copied plugin before any public distribution
   ([license](https://github.com/cursor/plugins/blob/799151d91b6e12ee7dbd09f708eec108d7de9b3b/pstack/LICENSE)).

## Proposed destination families

These are planning families, not bundled plugins. Each reusable skill remains
independently installable.

| Family                  | Standalone destinations or existing target                                                                                    | Notes                                                                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Router                  | A new solo workflow router                                                                                                    | Replace `poteto-mode`; route by goal, not Cursor command syntax.                                                                       |
| Principles              | One plugin per retained `principle-*` skill                                                                                   | Copy semantic leaves; adapt renamed skills and any skill that adds standalone dependency, authority, safety, or coordination guidance. |
| Understand              | `how`, `why`, `explain-code`, `recall`, `blast-radius`                                                                        | Remove team chat and use host-neutral subagents/transcripts.                                                                           |
| Design and review       | `architect`, `arena`, `interrogate`, `swarm`                                                                                  | Preserve internal multi-agent work and agent-to-agent communication.                                                                   |
| Build and verify        | `regression-test`, `create-verification-skill`, `maintain-verification-skill`, bug/perf/feature/prototype/forensics playbooks | Extract the narrow regression seam and use capability language for browser, terminal, simulator, and app control.                      |
| Personal workflow       | `automate-me`, `reflect`, `show-me-your-work`, `figure-it-out`                                                                | Keep artifacts local; never file tracker items automatically.                                                                          |
| Writing                 | `unslop`, `technical-writing`, `bro`                                                                                          | Copy `unslop` and `bro`; adapt technical-writing links and ASCII spelling.                                                             |
| Language guidance       | `typescript-best-practices`                                                                                                   | Adapt the skill's sibling-skill references for standalone use; copy its patterns reference.                                            |
| Existing target plugins | `safe-refactor`, `commit-guidelines`, `fix-all-issues`                                                                        | Fold distinctive refactor, PR-authoring, and review ideas into these only after a gap check; do not create near-duplicates.            |

## Dependency and adaptation rules

The port should not preserve pstack's hidden runtime assumptions. Apply these
rules consistently rather than fixing each copied file ad hoc.

1. **Subagents:** say what role, scope, evidence, and output a subagent needs.
   Use the host's available spawn/wait/message capability. Do not name Cursor
   `Task`, `generalPurpose`, `readonly`, `environment: "cloud"`, or
   `run_in_background` fields in reusable prompts.
2. **Models:** inherit the parent model unless the host exposes a portable role
   override. Never hard-code Cursor marketplace model aliases. Make model
   diversity a preference, not a required slug.
3. **Transcripts and stores:** use paths supplied by the current environment.
   Do not search a home-wide Cursor tree. Fail closed or use a user-provided
   digest when the host exposes no scoped transcript.
4. **Control surfaces:** ask for a capability (browser, terminal, simulator,
   app-control adapter), then use the best installed local skill. Do not depend
   on `cursor-team-kit`, `control-ui`, or `control-cli` by name.
5. **Skill invocation:** refer to destination skill names and let the host's
   skill mechanism load them. Replace Cursor slash-command and built-in
   assumptions.
6. **Delivery:** local edits, tests, evidence, commits, and draft text are valid
   outputs. Never post a review reply, tracker comment, issue, Slack message, or
   other human-directed external communication. Skills that can prepare a PR
   body return the draft to the user.
7. **Existing target overlap:** compare source behavior against
   `safe-refactor`, `commit-guidelines`, and `fix-all-issues` before creating a
   new plugin. Add only a distinctive behavior; do not fork two competing
   policies.

## Extraction waves

### Wave 0: establish the shared contract

- Add the MIT third-party notice strategy.
- Add the no-external-communication invariant to the target agent/plugin
  authoring guidance and an acceptance scan for disallowed send verbs/tools.
- Define the host-neutral vocabulary for subagents, transcript scope, control
  capabilities, and skill-to-skill invocation.
- Decide the router's new name. Do not retain `poteto` author branding unless
  the user explicitly wants it.

### Wave 1: copy the portable leaves

- Copy the unchanged principle skills and adapt the few with standalone dependency, authority, or communication guidance.
- Adapt and add `principle-never-block-on-the-human` in the same wave so the
  suite cannot inherit pstack's confirmable external-message exception.
- Copy `bro`, `unslop`, the portable templates, the TypeScript patterns, and
  the decision log helper/template. Adapt `teach` as `explain-code`, extract
  the narrow `regression-test` behavior from `tdd`, and adapt
  `technical-writing` and `typescript-best-practices` where the target's
  canonical skills or standalone fallbacks take precedence.
- Give every one its own target plugin shell and metadata.

### Wave 2: adapt focused workflows

- Port `how`, `architect`, `arena`, `interrogate`, `swarm`, `blast-radius`, and
  `why` using the shared host-neutral vocabulary.
- Port verification creation/maintenance, bug fix, perf, prototype, visual
  parity, and forensics. Stop at local evidence and a user-facing handoff.
- Port `automate-me`, `recall`, `reflect`, `show-me-your-work`, and
  `figure-it-out` only after scoped transcript discovery is defined.

### Wave 3: router and guide

- Create the optional router after leaf names and dependencies are stable.
- Rewrite the useful guide chapters around solo workflows.
- Add host-neutral recipes and regenerate art only when it materially helps.

### Wave 4: optional concept extractions

- Gap-check refactoring against `safe-refactor` and PR/commit prose against
  `commit-guidelines`.
- Consider a small plan validator and local long-program ledger only after a
  real destination workflow proves the need.
- Keep Graphite, Benny, Slack, Bugbot/watch-pr, automated review-thread, and
  bot-webhook components excluded.

## Acceptance checks for implementation

Each destination plugin should pass all of these before the extraction is
considered faithful:

- Its source component and classification appear in this inventory.
- Its manifest, skill frontmatter, command, README, and Codex metadata match the
  target repo's one-plugin convention and version rule.
- Subagent use is internal and can include agent-to-agent communication.
- No instruction can send or delegate a human-directed external message.
- No Slack/team-chat source, route, credential, connector, or example remains.
- No Cursor-only path, built-in, model slug, task field, cloud-agent URL, or
  transcript assumption remains unless it is explicitly documented as an
  optional adapter.
- Copy-class artifacts differ only for packaging, links, metadata, ASCII
  normalization, and license notices.
- Adapt-class artifacts have tests or dry-run scenarios for host-neutral
  routing and the external-communication boundary.
- Excluded components are absent from manifests and router descriptions.
- `bun run format` and `bun run format:check` pass in the target repository.

## Bottom line

Copy the leaves, adapt the coordinators, and remove the communication machinery
at the source. The result should be a collection of small, independently
installable solo-development skills plus an optional router, not a renamed
monolith. The largest reusable body is pstack's principles and evidence-driven
workflows. The parts that should not cross the boundary are Benny, Slack, Grok
Bot routines, Graphite/autopilot shipping, automated review-thread handling,
and their watch-pr runtime.
