# Prototype

Use to settle a design or behavioral question with a throwaway artifact.

1. Invoke `prototype` when installed. Otherwise use the remaining steps as the complete local throwaway workflow. State the one decision the artifact must resolve.
2. Gather references only when the design direction is open.
3. Build in an isolated scratch directory, separate from production source. Use the lightest stack that can expose the decision.
4. Put alternatives behind one labeled switcher when comparison matters.
5. Drive the artifact on the matching surface. Capture screenshots for visual decisions and measured output for behavioral decisions.
6. Present tradeoffs and a recommendation. Do not promote prototype code into production unchanged.

Return the decision, variants, evidence, recommendation, and scratch path. State that the artifact is throwaway.
